# Diagramme – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard (Variante B), Alerts-Tab (Variante A), Sysmon, ThreatScan, Submit, Graph-Detail und Detonationsergebnis bekommen eigene SVG-Diagramme und Sankeys, in beiden Themes, mit Klick-Filtern, (i) und CHART/TABLE.

**Architecture:** Ein kleiner Diagramm-Baukasten aus reinen Funktionen in `app.js` (Zählen/Einteilen der Daten → Layout → SVG-Markup), Farben als `var(--…)` im SVG, sodass ✶ ohne Neuzeichnen umfärbt. Die Ansichten rufen den Baukasten mit Daten aus `state.alerts`, den geladenen Sysmon-Ereignissen, dem Scan-Verlauf, den Einreichungen, den Graph-Daten und den Detonationsergebnissen auf. Einzige Server-Änderung: das Urteil wird je Einreichung gespeichert.

**Tech Stack:** Vanilla JS (`webui/static/js/app.js`, kein Build), SVG, CSS, Flask (`webui/app.py`), pytest + Node.

**Spec:** `docs/superpowers/specs/2026-11-10-charts-design.md`

**Mockups (Vorlage für das Aussehen, mit echten VM-Daten):** `.superpowers/brainstorm/34131-1794300555/content/charts-v2.html` (Dashboard B, Alerts A, weitere Ansichten) und `.../content/sankey-v1.html` (Sankeys), Generator-Skripte unter `/private/var/folders/z1/5108m1hd4lx_m3__94n64bz40000gn/T/opencode/charts/` (`gen.py`, `sankey.py`).

## Global Constraints

- Keine Diagramm-Bibliothek, keine neuen Abhängigkeiten, kein Build-Schritt; JavaScript als Funktionen auf oberster Ebene in `app.js` (Tests ziehen sie per `_function_source`).
- `style.css` nur mit Variablen aus `:root` (Tests verbieten Farb-Literale); `theme-cyberpunk.css` nur unter `[data-theme="cyberpunk"]`.
- Farben in SVG als `var(--…)` (`fill`/`stroke` per `style` oder Attribut); Schweregrade aus `--severity-critical|high|medium|low|info`; keine Farb-Literale in `app.js`.
- Jede neue Diagramm-Karte hat ein `data-info` (i) und den CHART/TABLE-Schalter (`viewToggleHtml`/`cardViewAttrs`); die Tabellenansicht zeigt dieselben Zahlen, `table[data-sortable][data-sort-id]`.
- Alle Daten-Texte (Regeln, Prozesse, Images, Dateinamen) über `escapeHtml` in SVG-`<text>`, `<title>`, Attributen und Tabellen; Handler nur mit `jsArg`/`jsInt`.
- Dashboard-Zeitraum: Schalter `24H` / `7D` / `30D` / `ALL`, Standard `ALL`.
- Sankey: mindestens 6 einzelne Regeln/Prozesse/Images, Rest als `other rules` / `other processes` / `other images`; Standard gestaucht (Wurzel), Schalter `LINEAR`.
- Score-Schwellen: SUSPICIOUS `2`, MALICIOUS `6`; Scans ohne Score in der Spur `no score`.
- Einreichungen ohne gespeichertes Urteil: grau, „not evaluated“.
- Leere Daten zeigen einen Hinweis statt einer Grafik („No alerts in this range“, „Sysmon not available“, „No scans yet“, …).
- Classic ändert sich nur durch die neuen Karten und das Ganz-Tab-Scrollen von Alerts und Sysmon (stehende Filterleiste).
- Oberfläche und README Englisch; Asset-Versionen in `index.html` erhöhen; Sichtprüfung auf der VM mit selbst gestartetem Chrome (nie an einen bestehenden Debugging-Port hängen).

## Review Focus

1. **Bösartige Beschriftungen** – Regel-/Prozessnamen mit `<`, `"`, `&` in SVG-Text, Tooltip und `data-*` bleiben Text (Node-Tests in Task 1 und 2).
2. **Entartete Daten** – null Alerts, ein einziger Abschnitt, alle Werte 0, ein Segment mit 100 % (ein SVG-Bogen von einem Punkt zu sich selbst zeichnet nichts) → Hinweis bzw. voller Kreis (Tests in Task 1).
3. **Polling-Kosten** – 10 000 Alerts, Neuzeichnen alle 5/10 s: Zählen nur bei geänderter Datenliste oder geändertem Zeitraum (Test in Task 5, Messung im Bericht).
4. **Zeitzonen** – Tagesgrenzen der Zeitachsen in Ortszeit; Tests laufen in CI unter UTC und Europe/Berlin und dürfen von keiner Zone abhängen (Test in Task 1).
5. **Klick-Filter-Rundweg** – ein Klick auf Segment/Balken/Strom setzt einen sichtbaren, entfernbaren Filter, und die Tabelle zeigt genau so viele Zeilen wie das Diagramm zählte (Tests in Task 3 und 4).

**Interfaces – Produces:**
- `SEVERITY_ORDER = ['critical', 'high', 'medium', 'low', 'info']`
- `alertCategory(alert) -> string` – erste Kategorie, klein geschrieben, aus Liste oder Text (`["registry"]` → `registry`, `process` → `process`), leer → `other`.
- `countBy(items, keyFn) -> [{key, count}]` – absteigend nach `count`, bei Gleichstand nach `key`.
- `binByTime(items, {time, key, keys, from, to}) -> {unit, bins}` – `time(item)` liefert ms oder `NaN` (übersprungen); `unit` ist `'hour'` bei Spanne ≤ 2 Tage, `'day'` bei ≤ 120 Tagen, sonst `'week'`; Grenzen in Ortszeit (Mitternacht bzw. volle Stunde, Woche ab Montag); `bins = [{start, end, counts: {<key>: n}, total}]` lückenlos von `from` (oder frühestem Element) bis `to` (oder spätestem).
- `stackedBarsSvg(bins, {width, height, keys, colors, selection}) -> string` – je Abschnitt ein `<g data-bin-start data-bin-end>` mit `<rect>` je Schlüssel, `<title>` mit Zeitraum und Zahlen; Achsenbeschriftungen; `selection = {from, to}` zeichnet die Auswahl.
- `donutSvg(items, {size, thickness, centerLabel, centerSub}) -> string`, `pieSvg(items, {size}) -> string` – `items = [{key, label, value, color}]`; Segmente mit `data-key`; ein Element mit 100 % zeichnet einen vollen Kreis; alle 0 → `''`.
- `chartLegendHtml(items, {total}) -> string` – Farbe, Name, Anzahl, Anteil; Zeilen mit `data-key`.
- `sparklineSvg(values, {width, height, color}) -> string`.
- `scatterSvg(points, {width, height, yMax, thresholds}) -> string` – `points = [{x, y, color, title, key}]`, `y === null` → Spur „no score“ unter der Achse; `thresholds = [{y, label}]` gestrichelt.
- `chartEmptyHtml(text) -> string`.
