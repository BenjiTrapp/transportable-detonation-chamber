# Handbuch-Website auf GitHub Pages — Umsetzungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aus denselben vierzehn Markdown-Seiten, aus denen `make docs` das Offline-Wiki baut, entsteht eine Handbuch-Website mit einer Adresse je Seite, Navigation, Suche und gezeichneten Diagrammen, die ein Workflow bei jedem Push auf `main` auf GitHub Pages veröffentlicht.

**Architecture:** `scripts/build-wiki.py` bekommt eine zweite Ausgabe. Parser, Suchindex-Bau, Überschriften-Auslese und das Prüfsummen-Tor für Mermaid bleiben dieselben Funktionen; neu sind eine Verweis- und Bild-Strategie für mehrere Dateien, eine Seitenhülle (Kopf, Register, Vor/Zurück, Fuß) und ein Schreiber, der je Seite einen Ordner mit `index.html` anlegt. Die Markdown-Dateien ändern sich nicht.

**Tech Stack:** Python 3.9 (nur Standardbibliothek), Mermaid 10.9.3 (gepinnt, aus dem Repository ausgeliefert), GitHub Actions (`upload-pages-artifact`, `deploy-pages`), pytest.

**Spec:** `docs/superpowers/specs/2026-11-18-docs-site-design.md`

## Global Constraints

- **Eine Quelle:** Die Website entsteht aus `docs/*.md` und `README.md`. Kein Satz wird für sie zweitgeschrieben, keine Markdown-Datei bekommt einen YAML-Kopf oder einen geänderten Bildpfad.
- **Sprache:** Website, Doku und Code-Kommentare englisch; dieser Plan und der Entwurf deutsch.
- **Python 3.9, nur Standardbibliothek**, keine neue Abhängigkeit, auch nicht für die CI.
- **Keine Anfrage nach außen zur Laufzeit:** kein CDN, kein `img.shields.io`, keine Schriften von fremden Servern. Mermaid kommt als `assets/mermaid.min.js` von derselben Seite, in der gepinnten Fassung (`MERMAID_VERSION`, `MERMAID_SHA256`); fehlt die Kopie oder stimmt die Prüfsumme nicht, bricht der Bau ab.
- **Alle Verweise relativ** (`../rizin/`), keiner beginnt mit `/`: die Seite liegt unter `/transportable-detonation-chamber/` und muss auch aus einem lokalen Ordner aufgehen.
- **Fünfzehn Adressen:** `/` (aus `README.md`), `/guide/` (aus `docs/README.md`) und je eine je Doku-Seite in der Reihenfolge von `page_order`. `docs/superpowers/` wird nie veröffentlicht.
- **Markdown wird nicht lebendig:** derselbe Parser, dieselbe Entschärfung; ein `<script>` oder `onerror=` aus einer Doku-Seite bleibt Text.
- **Mermaid nur auf den Seiten mit Diagramm** (heute fünf: `/`, `/guide/`, `/workflow/`, `/memory/`, `/rizin/`), nicht auf den anderen zehn.
- **Erzeugtes bleibt erzeugt:** `site/` und `webui/static/wiki.html` sind git-ignoriert; nichts davon wird eingecheckt.
- **Keine lokalen Pfade und kein Rechnername** in der Ausgabe; die Fußzeile trägt Baudatum (UTC) und kurze Commit-Kennung.
- **Das Offline-Wiki bleibt, wie es ist:** `tests/test_wiki.py` bleibt grün, `make docs` unverändert.
- **Tests:** `make -s unit-test` grün (Stand vor dieser Arbeit: 1270 bestanden, 1 übersprungen), die volle Suite je einmal unter `TZ=UTC` und `TZ=Europe/Berlin`; Node 20 als erste Stelle im PATH.
- **Repo-Regeln:** kein Name der früheren Vergleichs-Software des Hex-Editors, keine interne Referenz-Seite.

## Review Focus

1. **Eine Doku-Seite, die der Index nicht verlinkt,** fehlt auf der Website, ohne dass es auffällt — `page_order` liest nur `docs/README.md`. Test in Task 2: jede `.md` unter `docs/` außer `superpowers/` hat eine Adresse auf der Website.
2. **Zwei gleiche Überschriften auf einer Seite** (`## Limits` in zwei Abschnitten) geben zweimal dieselbe Sprungmarke; ein Treffer der Suche landet dann an der falschen Stelle. Test in Task 1: Sprungmarken sind je Seite eindeutig, auch bei doppeltem Text.
3. **Ein Verweis mit Sprungmarke auf eine andere Seite** (`docs/README.md#detection-engines` aus der README, `web-ui.md#charts` aus `logs.md`) muss `../guide/#detection-engines` werden — Datei **und** Marke, nicht nur die Datei. Test in Task 1.
4. **Ein Bild, das `static/` nicht hat,** ist im Wiki ein Platzhalter und auf der Website ein 404. Test in Task 2: ein fehlendes Bild bricht den Bau mit Meldung ab, statt eine toten Verweis zu veröffentlichen.
5. **Ein Verweis, der über die Wurzel der Seite hinausgeht** (`../x/` von `/index.html` aus) ist unter dem Unterpfad von GitHub Pages tot. Test in Task 2: jeder relative Verweis löst innerhalb des Bauordners auf.
